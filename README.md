# Time Grid - Obsidian 插件

极简主义的时间管理与可视化工具 - 向死而生 (Memento Mori)

在 Obsidian 右侧面板提供两个视图：**时间视图**让你直观感受时间的流逝与去向，**任务视图**是一个读写全库任务的任务中心。所有数据都存在你自己的 Markdown 笔记里，插件不建立任何数据库。

## 功能特性

### 时间视图

日晷式的「此刻回环」布局，由外到内层层收敛到当下：

- **长期轨迹**：贡献图式的活动热力图，可在近 3 个月 / 6 个月 / 1 年之间切换并记住选择（默认 6 个月）。格子强度按日记中 `simple-time-tracker` 的计时时长计算
- **本月位置**：当月日期网格，过去日期为深色，今天红色轮廓高亮
- **今日进度**：外圈 24 小时刻度 + 内圈当前小时的 60 分钟刻度，实时推进
- **内置计时器**：可以直接在面板里开始、停止和原子切换计时。快捷建议合并最近 7 天的活动、今日/逾期任务和今日流程并去重
- **今日去向**：当天计时分布的圆环图，含中心总时长、Top 5 + 其他合并、图例悬停联动，以及无日记 / 无计时块 / 格式错误 / 空记录 / 进行中的分状态显示
- **写作增量**：摘要同时显示计时总量与全库 Markdown 的新增字数

### 任务视图

一个完整的任务中心，读取全库符合 Tasks 插件 emoji 语法的任务：

- **六分区**：逾期、今天、待分类、长期、未来、已结束。未来再细分明天 / 7 天内 / 更晚；完成与取消合并进已结束但保留状态区分
- **四态管理**：待办、进行中、完成、取消，可选记录完成 ✅ / 取消 ❌ 的终态日期，重新打开时自动移除
- **编辑与快捷操作**：编辑描述、到期日、优先级和长期标签；删除（二次确认）、顺延一天、Shift 顺延一周、待分类区的「设为今天 / 设为长期」
- **搜索与筛选**：即时搜索覆盖描述、标签和文件路径；状态、优先级、来源类别之间是 AND，同类选项之间是 OR
- **从任务直接计时**：任务卡的更多菜单可以直接启动计时，支持自定义标题；运行中会要求确认原子切换，待办任务计时成功后自动转为进行中
- **每日流程 (Routine)**：用一篇专用配置笔记管理多个流程组合与未来计划，每天在日记里生成真实的 checklist 实例。不使用 Tasks 的 `🔁` 语法
- **异常任务只读**：格式异常、未知状态和循环任务仍然显示，但标注为只读并拒绝写入

## 数据来源与依赖

Time Grid 不存储任何业务数据，全部读写你的笔记：

| 数据 | 来源 | 依赖 |
|---|---|---|
| 计时记录 | 日记中的 `simple-time-tracker` 代码块（**唯一真相源**） | Obsidian 核心「日记」插件 |
| 任务 | 全库 Markdown 中的 Tasks 插件 emoji 语法任务行 | 无（自行解析，不依赖 Tasks 插件运行） |
| 每日流程 | 专用配置笔记（默认 `00-Templates/Time Grid Routines.md`）+ 每天日记里的实例 | Obsidian 核心「日记」插件 |
| 新增字数 | 插件启用后建立的全库 Markdown 字数基线 | 无 |

插件自身的 `data.json` 只保存设置、面板折叠状态、字数基线和一个兼容的计时恢复指针。

## 数据安全

这个插件会写入你的笔记，所以写入路径做了这些约束：

- 所有写入都经过 `Vault.process()` 重新读取并原子写回，不做覆盖式整文件写入
- 写入前要求目标原文在文件中**全局唯一**；找不到、重复、循环任务、异常和未知状态一律拒绝写入并重新索引，**绝不猜测**
- 任一时刻只允许一个运行中的计时；多个运行项、多个计时块或异常 JSON 会进入诊断状态并拒绝自动写入
- 计时切换用同一个时间戳结束旧段并开始新段，不产生空隙或重叠
- 运行中的计时在本地午夜自动拆分；关闭期间跨日超过 24 小时必须由你手动选择如何处理
- 解析时保留未识别的字段（`🔁`、`🆔`、自定义文本、JSON 未知键）
- 旧日记模板迁移到每日流程前必须先显示预览并由你确认
- 插件自己写入造成的字符差异会从「新增字数」中扣除，不污染写作统计

## 安装方法

### 方法一：手动安装（推荐）

1. 找到你的 Obsidian vault 目录（通常是你的笔记文件夹）
2. 在 vault 目录下找到 `.obsidian/plugins/` 文件夹（如果不存在则创建）
3. 将整个 `TimeGrid` 项目文件夹复制到 `.obsidian/plugins/time-grid/` 目录
4. 确保以下文件存在于插件目录：
   - `main.js`
   - `manifest.json`
   - `styles.css`
5. 打开 Obsidian，进入 设置 → 第三方插件 → 已安装插件
6. 找到 "Time Grid" 并启用

### 方法二：使用安装脚本

先构建，再运行安装脚本（需要替换 `YOUR_VAULT_PATH` 为你的实际 vault 路径）：

```bash
npm run build && ./install.sh YOUR_VAULT_PATH
```

安装后需要关闭/开启 Time Grid 插件、执行 Reload app without saving，或重启 Obsidian 才能加载新的 JS/CSS。

## 设置项

插件设置页分两组：

**每日流程**

| 设置 | 类型 | 默认值 |
|---|---|---|
| 启用每日流程 | 开关 | 开 |
| 流程配置笔记 | 文本（vault 相对路径） | `00-Templates/Time Grid Routines.md` |

**任务**

| 设置 | 类型 | 默认值 |
|---|---|---|
| 启用任务面板 | 开关 | 开 |
| 排除路径 | 文本（逗号分隔） | `00-Templates` |
| 长期任务标签 | 文本 | `#goal` |
| 显示任务所在文件名 | 开关 | 关 |
| 记录终态日期 | 开关 | 开 |
| 已完成区显示范围 | 下拉（仅今日 / 近 7 天 / 全部） | 仅今日 |
| 每区最多渲染条数 | 数字 | 50 |

## 开发

```bash
# 安装依赖
npm install

# 开发模式（自动监听文件变化）
npm run dev

# 构建插件（TypeScript 检查 + 生产打包）
npm run build

# 运行测试
npm test
```

`npm test` 包含两部分：72 个核心纯函数用例（解析、排序、分区、序列化、计时状态机），以及在独立临时 Git vault 中执行的真实文件写入集成验证——每日流程 24 次写入、计时器 9 次写入，覆盖并发陈旧写回拒绝、跨午夜拆分和危险内容拒写。

## 注意事项

- 插件会在 Obsidian 右侧面板自动显示，无需配置即可使用
- 时间视图每秒刷新一次；切换到任务视图时会暂停这个刷新，但任务索引和午夜重新分区继续工作
- 活动热力图的格子强度与今日去向依赖 Obsidian 核心「日记」插件和日记中的 `simple-time-tracker` 代码块
- 新增字数统计从插件启用后建立基线，**不回填历史新增字数**
- `simple-time-tracker` 时长按当前日期边界裁剪，避免跨日计时污染单日统计
- 大型 vault 首次索引会异步分批进行并显示索引中状态
